# 方法与图例

## 这是什么

对 **豆包工作（Doubao Work）** Agent 云沙箱运行时的 **观察型 teardown** 笔记。  
材料来自产品对话内的现场取证（让模型在沙箱里执行命令、读配置、测网络）。**非**字节 / 火山官方文档。

## 图例

| 标记 | 含义 |
|------|------|
| **实测** | 有路径、命令、响应头或挂载证据 |
| **推断** | 由旁证推出，未直接读到配置 |
| **未测到** | 尝试过但仍缺证据 |

## 方法

1. 在 Doubao Work 中要求 Agent 做分层勘察（计算 → 网络 → Agent 面 → 暴露 → IO → 指纹）。
2. 只采信可复核标识：路径、环境变量名、模块名、端口、工具名。
3. 结论合并进 [`docs/`](.) 对应主题；轮次记入 [`../changelog.md`](../changelog.md)。
4. 不入库密钥、Cookie、完整他人会话正文。

## 局限

- 随 `IMAGE_VERSION` / FaaS revision 变化。
- 外层网关、加密参数、平台调度策略可能在容器外。
- 模型可能误读；重要结论要求「命令 + 路径」。

## 相近工作（对照阅读）

业界同类常称 *agent sandbox / runtime teardown*，例如对 Bedrock AgentCore、Claude Managed Agents 的拆解。本仓是 **观测笔记**，不是漏洞利用指南。
