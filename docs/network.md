# 网络与出口

> **范围说明：** 下面的域名能否访问，只是当次抽样，不是完整名单。出口公网 IP 会轮换，不要把它当成永远不变的基础设施。

## 一句话结论（实测）

算力跑在火山引擎的网络里；你在公网上看到的「来源 IP」，往往是 **VortexIP 代理落地之后的地址**（当次还落到过注册在阿里云 ASN 下的地址）。  
所以「像火山又像阿里」并不矛盾：计算层和出口层不是同一层。

## 容器里的网络（实测）

网卡地址是内网地址。默认网关的形态符合 Kata 常见配置。  
容器里还跑着本地代理组件，例如 tinyproxy（8118 端口）、gost，以及 `lark_hijack_proxy`。浏览器流量也会走本地代理。  
访问 GitHub 一类站点时，有可能被透明转到内网镜像地址（形如 `192.168.255.x`）。

## 流量怎么出门（实测）

可以概括成：

```text
容器里的 curl / Chrome
  → 本地 tinyproxy / gost / hijack
  → VortexIP（当次见过 cn-beijing2 一类域名）
  → 公网落地 IP（多沙箱共享，NAT）
```

因为很多沙箱共用少数出口 IP，外部服务若按 IP 限流（例如未登录的 GitHub API），就容易「一人超限、大家一起倒霉」。

## 管控（实测抽样）

1. **DNS / 路由：** YouTube、Wikipedia、BBC 等当次解析异常或超时；Google 类站点当次也不可用。  
2. **放行样例：** GitHub、arxiv、dev.to、Cloudflare 等技术向站点当次可通；不少国内站点直连很快。  
3. **云元数据接口：** 常见的云厂商元数据地址当次返回禁止访问——这是防止从沙箱里偷云凭证的常见加固。

出网带宽的硬上限在容器里 **未测到**（更可能在网关侧）。

飞书 / Lark 相关域名还会被本机劫持组件接管，证书由沙箱本地 CA 签发，鉴权回平台管控面。细节见 [product-fingerprint.md](product-fingerprint.md) 与 [evidence/2026-09-24/05-hijack-domains-redacted.md](../evidence/2026-09-24/05-hijack-domains-redacted.md)。  
说明：这是沙箱内部的流量接管方式，本仓只作观察记录，不提供对外攻击用法。

## 包管理源（实测）

| 工具 | 显式默认配置 | 实际怎么走 |
|------|--------------|------------|
| npm | 阿里 npmmirror 公开镜像 | 经网关到该镜像 |
| pip | 配置指向官方 PyPI | 经内网透明缓存网关再出门 |
| 手动改回 npm 官方域名 | registry.npmjs.org | 同样会进透明代理 |

响应头里能看到真实的 Cloudflare / Fastly / S3 痕迹，说明这是 **带缓存的转发**，不是伪造包内容的假源。

## 证据从哪来

出口 IP 查询、DNS 对比、带远端 IP 的 curl、代理相关环境变量与进程、npm/pip 配置与响应头。
