# 方法与图例

## 这是什么

这份笔记拆解的是 **豆包工作（Doubao Work）** 里 Agent 使用的临时 Linux 云沙箱。  
材料来自产品对话中的现场取证：让模型在沙箱里执行命令、读取配置、探测网络。  
**这不是** 字节跳动或火山引擎的官方文档。

## 图例

| 标记 | 含义 |
|------|------|
| **实测** | 有路径、命令、响应头或挂载等可核对证据 |
| **推断** | 由旁证推出，并没有直接读到对应配置 |
| **未测到** | 尝试过，但仍然缺少证据 |

## 方法

1. 在豆包工作中要求 Agent 按层勘察：计算、网络、工具面、对外暴露、文件进出、产品指纹。  
2. 只采信可以复核的标识：路径、环境变量名、模块名、端口、工具名。  
3. 把结论写进 `docs/` 里对应的主题文；把「哪天补了什么」记在 [`../changelog.md`](../changelog.md)。  
4. 不把密钥、Cookie、他人会话全文放进仓库。

## 局限

- 沙箱镜像版本（环境变量里的 `IMAGE_VERSION`）或函数修订号一变，下面的结论都可能失效。  
- 外层网关、加密参数、平台调度策略可能根本不在容器里，沙箱内看不到。  
- 模型可能误读；重要结论应同时带上「用了什么命令、读了什么路径」。

## 相近工作

业界常把这类文章叫做 *agent sandbox / runtime teardown*。  
本仓是观察笔记，不是漏洞利用指南。
